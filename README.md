# Flyway Web Acceptance

面向飞来汇 Web 产品的 AI 验收 Skill，通过 Chrome DevTools MCP 检查业务流程、页面状态和设计还原情况，输出带复现步骤、截图与技术证据的问题清单。

适合产品、设计和前端在联调、提测、上线前验收时使用。仓库提供验收规则与工作流程，需要由支持 Skill 和相关 MCP 工具的 AI 助手执行。

## 支持哪些验收

| 模式 | 验收依据 | 重点检查 |
|---|---|---|
| 产品功能验收 | PRD、验收标准、已确认业务规则 | 主流程、取消与返回、输入校验、异常处理、权限和业务状态 |
| 设计前端还原度验收 | 指定 Figma 节点、组件、变量和样式 | 布局、字体、间距、颜色、组件状态、浮层和响应式表现 |

可以单独执行，也可以在同一次任务中执行两类验收。两类问题分别判断，共享登录、页面基线、Console 和 Network 检查。

## 使用前准备

### 工具

- **Chrome DevTools MCP**：用于页面快照、交互、截图、Console、Network 和页面数值取证，是主要执行工具。
- **Figma MCP**：设计还原验收时，用于读取指定节点及设计属性。
- **lark-cli / 飞书技能**：验收依据或问题表位于飞书时使用；写入问题表需要目标文档的编辑权限。
- **flyway-b-design Skill**：验收飞来汇 B 端的设计还原度时需同时安装，用于核对设计规范、组件、Token 和响应式规则。

这些依赖需单独配置，克隆本仓库不会自动安装或授权。Chrome DevTools MCP 未加载时，需先完成配置并重启或新建会话；只有用户明确同意，才降级使用 Computer Use。

### 验收资料

- 测试 URL、环境、模块，以及已登录的测试账号和角色。
- 功能验收对应的 PRD、验收标准或业务规则。
- 设计验收对应的 Figma 链接、精确 `node-id` 和基准视口。
- 允许操作的测试数据、禁止执行的操作，以及明确忽略的检查项。
- 结果交付位置：对话中的问题清单，或指定的飞书问题表。

## 安装

将仓库克隆到当前 AI 助手的 Skill 目录下，并保留目录名 `flyway-web-acceptance`。例如，使用 `~/.codex/skills` 作为 Skill 目录时：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/damonlior/flyway-web-acceptance.git \
  ~/.codex/skills/flyway-web-acceptance
```

如果已经安装，请在原目录更新，避免重复克隆：

```bash
git -C ~/.codex/skills/flyway-web-acceptance pull --ff-only
```

在能够加载该 Skill 的会话中，使用 `$flyway-web-acceptance` 发起验收。工具连接与账号权限仍需按上面的准备要求配置。

```text
测试页面：<测试 URL>

目标模块：<模块名称>
账号角色：<角色，已登录>

禁止操作：<禁止事项>

覆盖主流程、取消返回、输入校验、空状态、权限和异常状态。

```

### 设计还原与响应式验收

```text
使用 $flyway-web-acceptance 做设计前端还原度验收。
飞来汇 B 端页面同时使用 $flyway-b-design。

测试页面：<测试 URL>
设计稿：<包含 node-id 的 Figma 链接>
基准视口：<与设计 Frame 一致的宽 × 高>

记录布局和样式的实际数值、设计预期、差值及截图。

```

### 写入飞书问题表

如需保存结果，在验收指令中补充：

```text
将本次确认的问题追加到：<飞书问题表链接>。
保留原表头、已有内容、列宽、图片和样式，延续现有序号。
写入后重新读取，核对新增行、序号、图片和关键文本。
```

## 验收结果

每次交付说明已完成范围、未验证范围及问题数量。验收结论分为：

- **通过**：实际结果符合验收依据，关键状态已覆盖，没有相关 Console / Network 异常。
- **不通过**：有明确依据、稳定复现步骤和实际偏差。
- **待验证**：受账号权限、测试数据、环境或未获授权的操作阻塞，并记录原因。

问题表使用固定结构：

| 序号 | 模块 | 问题描述（截图）/ 期望效果 | 优先级 | 提交人 | 处理人 | 处理进度 | 备注 |
|---|---|---|---|---|---|---|---|

一条独立根因的问题占一行。描述包含复现条件、实际结果、验收依据、期望效果和截图；备注记录 URL、视口、角色、接口状态、Console 摘要或 Figma 节点等证据。通过项不写入问题表。

| 优先级 | 含义 |
|---|---|
| P0 | 系统、资金或数据安全灾难级问题 |
| P1 | 核心流程阻断 |
| P2 | 局部功能异常，或明显的还原、响应式问题 |
| P3 | 轻微一致性问题 |

提交人可在任务中指定；未指定时沿用规则中的默认值。处理人未指定时留空，新问题默认“待处理”。完整字段规则见 [报告结构](references/report-schema.md)。

## 执行边界

- 以只读检查或受控测试交互为主；真实付款、提交认证、删除、发布、解绑、权限变更等动作，执行前需获得明确授权。
- 不通过隐藏遮罩、篡改请求或修改 DOM/CSS 完成业务流程。临时样式验证只作为“实验性修复”，不能证明原页面通过验收。
- 只记录有依据且可稳定复现的缺陷；环境阻塞、未经验证的风险和审美偏好分别说明。
- 不将 Cookie、Token、证件、账号内容等敏感信息写入报告。
- 只有明确要求写入飞书时才修改目标文档，并在写入后重新读取核对。
- 本 Skill 用于验收和记录问题，不负责实现或修复业务代码。
